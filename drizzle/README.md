此目录保存 0.1 起的 SQL 迁移和 Drizzle 元数据。

`0000_baseline.sql` 直接建立当前多用户账本、分类、导入记录及身份认证表，并建立复式分录的平衡函数和延迟约束触发器。它不包含开发期清空数据、单人账号切换或历史分类回填操作。

## 新数据库

运行 `pnpm db:migrate` 应用基线；重复执行不会重建表。新用户的账本和预设分类由应用创建。

## 已完成旧迁移的数据库

基线 journal 的 `when` 保持旧 `0003` 的时间戳 `1793726117622`。当前 Drizzle PostgreSQL migrator 按最后执行的时间戳判断待执行迁移，因此已完成旧 `0000`–`0003` 的数据库会跳过基线，保留数据及原有迁移记录，无需修改线上 journal 或执行建表 SQL。SQL 文件名的 `0000` 是新历史的序号，不代表重新执行旧初始化。

此接续方式仅适用于完整执行旧迁移链、结构与当前版本一致的数据库。未完成旧迁移的环境，应从 Git 中检出合并前的版本，完成旧迁移后再升级；不要删除已有数据库的迁移记录或强行重放基线。上线前先备份并核对最后迁移时间戳。

## 后续变更

修改 `src/db/schema.ts` 后执行 `pnpm db:generate`，审查生成 SQL，再运行 `pnpm db:migrate`。0.1 发布后仅追加增量迁移，不修改已经执行的基线或增量迁移。手写函数与触发器不由 schema 自动生成，修改它们时需显式添加 SQL。

迁移历史留在 Git；仓库仅保留一份基线 snapshot，后续 snapshot 随增量迁移生成。隔离集成测试验证基线初始化、重复执行、已有库接续、后续增量及数据库平衡约束。
