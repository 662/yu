# 记账与分类规则

## 金额与分录

金额使用整数分，数据库使用 bigint，应用按安全整数处理。单笔金额必须大于零且不超过 99,999,999,999 分；用户输入最多两位小数，交易日期必须是真实的 `YYYY-MM-DD` 日期。

每笔交易有两条有符号分录，合计为零，正数分录之和等于交易金额。服务端从命令重新生成分录；数据库延迟约束在事务提交时再次验证。内部科目（如 `expense:food`、`receivable`、`equity:opening`）与真实账户共用分录结构，因此分录的 `accountId` 不能简单视为真实账户外键。

| 类型 | 资金或科目变化 | 日常收支统计 |
| --- | --- | --- |
| 普通支出 | 付款账户减少，支出科目增加 | 计入支出 |
| 收入 | 收款账户增加，收入科目减少 | 计入收入 |
| 垫付支出 | 付款账户减少，应收款增加 | 不计入支出 |
| 报销到账 | 收款账户增加，应收款减少 | 不计入收入 |
| 转账、信用卡还款 | 转出账户减少，转入账户增加 | 不计入收支 |
| 期初、余额或估值调整 | 账户与权益科目之间变化 | 不计入收支 |

## 账户余额和资产

账户余额等于期初值加后续分录之和。创建账户时写入期初值，非零期初同时在数据库生成 `opening` 交易与权益分录；读快照时排除这笔交易，避免重复计算。

修改已有账户时，名称和备注可以修改，类型不能修改。填写的核对余额与当前余额之差生成独立调整记录，期初值保持不变。投资账户用同一机制记录估值，估值不能为负；信用卡欠款体现为负余额。账户名称不能重复。

资产汇总为所有账户正余额加待报销款；负余额的绝对值计为负债；净资产等于资产减负债。资产负债按余额符号汇总，不只按账户类型判断。

转账两端必须是不同的有效账户。信用卡还款额外要求转入账户为信用卡、转出账户不是信用卡。

## 垫付与报销的生命周期

报销可分次到账，累计不能超过原垫付金额，到账日期不能早于垫付日期。修改已有回款的垫付时，不能取消垫付标记、不能减到已收款金额以下，垫付日期不能晚于已有到账日期；已有回款时不能改成其他交易类型。

到账和余额调整记录仅支持删除后重新记录。删除原垫付会同时删除其关联报销回款，并重新计算余额与待报销额；这会影响账户余额，删除前应确认关联影响。

## 分类生命周期

每个账本独立保存支出与收入分类，初始为 8 个支出预设和 3 个收入预设。交易引用稳定分类 ID；改名只改变显示，历史交易和分录编号保持不变。

- 同一收支类型不能重名，比较时使用 NFKC 归一化并忽略大小写；每种类型最多 100 个分类。
- 分类创建后不能改变收支类型；排序命令必须覆盖该类型所有分类，包含停用项。
- 预设分类不能删除；已被账目使用的自定义分类只能停用，未使用的可删除。
- 每种类型至少保留一个启用分类。停用项不能用于新交易；原本属于该分类的历史交易仍可保留原分类编辑。
